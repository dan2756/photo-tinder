# PhotoKit implementation references

Read the objective and these fetched references before implementing `PhotoTinder/Library`:

- [Swift Concurrency README](https://github.com/AvdLee/Swift-Concurrency-Agent-Skill), current `skills/swift-concurrency/SKILL.md`, and its `actors.md`, `tasks.md`, `async-await-basics.md`, and `performance.md` references. The library and media loader own observable state on `MainActor`. `PhotoMetadataReader` owns metadata enumeration on a separate actor. Request cancellation and generation checks prevent an earlier asset's callbacks from replacing the current image.
- [Axiom README](https://github.com/CharlesWiltgen/Axiom), current `axiom-codex/skills/axiom-media/SKILL.md`, relevant permission, limited-library, observation, image-loading and performance sections of `skills/photo-library.md`, and the PhotoKit sections of its linked `skills/photo-library-ref.md`. These informed read/write permission handling, the native limited-selection picker, metadata classification, sized asynchronous images, progressive callbacks, iCloud progress, and a three-asset prefetch window.
- Axiom's `axiom-concurrency/skills/isolation-inheritance-diag.md`, specifically PhotoKit `performChanges` and `PHPhotoLibraryChangeObserver`. The observer is explicitly `nonisolated`; callbacks and change closures are explicitly `@Sendable`. No broad unsafe isolation or Sendable annotations were added.
- [Apple PHImageManager](https://developer.apple.com/documentation/photos/phimagemanager) and [Selfies smart album](https://developer.apple.com/documentation/photos/phassetcollectionsubtype/smartalbumselfportraits) documentation entry points. The web reader could not retrieve their Markdown bodies. API signatures and concurrency contracts were verified directly in the installed iPhoneSimulator26.5 SDK headers: `PHImageManager.h`, `PHPhotoLibrary.h`, `PHAsset.h`, `PHLivePhoto.h`, `PhotosTypes.h`, and `PHPhotoLibrary+PhotosUISupport.h`.
- Local `unslop/SKILL.md` for concise status and documentation wording.
- [Swift Testing README](https://github.com/AvdLee/Swift-Testing-Agent-Skill), current `swift-testing-expert/SKILL.md`, and `async-testing-and-waiting.md`, `parameterized-testing.md`, and `parallelization-and-isolation.md`. `MediaLoaderTests` uses explicit input/output size cases and a fresh loader for cancellation. Its cancellation test stays synchronously on `MainActor` until cancelling, so no Photos lookup begins and no timing-based wait is needed.
- The Swift Testing `migration-from-xctest.md` reference was also read before adding `PhotoKitIntegrationTests`. The domain tests remain Swift Testing. The read-only Photos checks use XCTest's runtime skip reporting for the exact disposable simulator UUID, authorization, and missing seeds. Observation notifications and the AVPlayer playback clock provide completion signals without timing-based sleeps.

The adapter uses actual screenshot metadata, the system Selfies album, and one record per Live Photo. Location comes only from existing asset metadata. Deletion re-fetches exactly the selected IDs, refuses partial availability, and returns IDs only after PhotoKit succeeds. A failed or cancelled library operation cannot mutate the app's queue through this adapter.

The integration review added cancellation for superseded metadata scans and periodic yielding during enumeration, allowing active-card lookups to proceed. Pixel bounds also clamp the rounded result so floating-point rounding cannot exceed the requested decode cap.

Validation: `xcrun swiftc -typecheck -swift-version 6 -strict-concurrency=complete`, targeting `arm64-apple-ios26.0-simulator` with iPhoneSimulator26.5.sdk, passed for `MediaItem.swift` and both library files. This verifies compilation; app integration and simulator behavior are recorded separately in the main verification report.

The six real PhotoKit integration tests read existing imported fixtures and never seed or delete library items. They cover metadata, smart classification, mixed shuffle, thumbnail loading and cancellation, card pixel content, and video playback. Running them requires the dedicated simulator, full authorization already granted through the app, and the fixture media from `test-support/media`. Actual execution results belong in the main verification report.
